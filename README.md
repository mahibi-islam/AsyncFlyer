# FLyer: Federated Learning-Based Crop Prediction

This repository reconstructs the method described in **“FLyer: Federated Learning-Based Crop Yield Prediction for Agriculture 5.0”**. The paper’s released experiment is a **crop recommendation/classification** task rather than a continuous yield-regression task: the cited dataset contains 4,513 rows with soil and environmental features and a crop label. Accordingly, this implementation uses an LSTM classifier, four edge clients, one cloud-held-out partition, FedAvg, AES-256-GCM encrypted model updates, and AES-256-GCM plus RSA-OAEP envelope encryption for local data-at-rest.

## Fidelity and unavoidable assumptions

The paper does not publish source code, random seeds, train/test split details, exact local epoch count, batch size, optimizer, sequence construction, or the latency/energy hardware measurement code. The implementation therefore makes those choices explicit in `configs/default.yaml` and records them in each run. The architecture follows the paper’s reported values: one LSTM layer with 64 units, two dense layers with 64 units, and a final softmax classifier. The paper reports sparse categorical cross-entropy and four edge servers. The optional client-sampling parameter follows Algorithm 2, while the default is full participation for a stable reproduction of the four-client experiment.

## Dataset

Download the Kaggle dataset referenced by the paper from <https://www.kaggle.com/datasets/sanchitagholap/crop-and-fertilizer-dataset-for-westernmaharashtra>. Place the CSV under `data/raw/` and pass its path with `--data`. The loader accepts common column aliases and automatically identifies the crop target. No synthetic data are generated by the training pipeline.

## Quick start

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m flyer.train --data data/raw/your_dataset.csv --rounds 10 --epochs 5
```

For a fast smoke test after installing dependencies:

```bash
python -m flyer.train --data data/raw/your_dataset.csv --rounds 1 --epochs 1 --batch-size 32
```

Outputs are written to `runs/<timestamp>/`, including metrics JSON, confusion matrices, encrypted-update audit records, and the final global model.

## Layout

`flyer/data.py` implements schema normalization, preprocessing, stratified global holdout, and the paper’s four-way client split. `flyer/model.py` defines the reported LSTM architecture. `flyer/crypto.py` implements authenticated AES-256-GCM for gradients/updates and RSA-OAEP-wrapped AES keys for local data. `flyer/federated.py` implements local training, encrypted update exchange, weighted FedAvg, and evaluation. `flyer/train.py` is the command-line entry point.

## Important interpretation

This is a faithful, runnable reconstruction of the published method, not the authors’ proprietary source code. Results should not be expected to match the paper’s >99% figures without the authors’ exact preprocessing, split, and training settings. The code never claims that encryption alone provides formal differential privacy or prevents all inference attacks; it protects updates in transit and local data at rest as described.
